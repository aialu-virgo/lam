Performance Desk on Google Apps Script

Set up once as ai.acp@virgoasia.com (or data@virgoasia.com). Every Virgo Google user can then open the Desk at your own link, with no claude.ai account. About 10 minutes, plus the data move.

Cutover rule: from the moment you download the backup (step 8) until the restore shows every section "ok", nobody uploads or edits on the claude.ai Desk.

  1. Create the project

    Open script.google.com › New project signed in as ai.acp@virgoasia.com. Name it Virgo Desk.

  2. Settings file

    Project Settings (gear) › tick Show "appsscript.json" manifest file in editor. Open appsscript.json, select all, paste:

    appsscript.json

  3. Server code

    Open Code.gs, select all, paste:

    Code.gs

  4. The Desk page

    + › HTML, name it exactly Index. Select all, paste (about 1.4 MB, the editor may take a minute), then Save:

    Index.html

  5. Run setup

    In the toolbar choose the function setup and press Run. Allow the permissions (Google Sheets and your email address). This creates the spreadsheet "Virgo Desk database (do not edit)" in your Drive.

  6. Deploy

    Deploy › New deployment › Web app. Execute as: Me. Who has access: Anyone within virgoasia.com. Deploy, then copy the Web app URL (ends in /exec). That is the link for all users. Send it to the Delivery Lead.

  7. Open it

    Open the /exec link yourself. You are a Super admin, so Admin is available.

  8. Download the backup

    On the claude.ai Desk: Admin › Tools › Download full backup, then save all files to your computer. If the page says data changed during the backup, run it again.

  9. Restore

    On the new Desk: Admin › Tools › Restore from backup, select all the backup files together. Keep the tab open until every section shows "ok". If it says "Restore incomplete", tick Replace everything and run it again.

  10. Check and share

    Admin › Tools › Measure store size confirms what loaded. Then share the /exec link with users who are in Admin › Users.

Connect SAP S/4HANA (read only, from 1 Oct 2026)

Do this after the Desk works. Super admin or project owner only. Nothing is ever written to SAP.

  1. Re-paste the three files (settings, server code, Index page) and make a New version. The settings file now asks for two more permissions (call SAP, set a daily trigger). Run setup once more and allow them.
  2. Project Settings (gear) › Script properties › add: SAP_BASE_URL (the https address only, no path), SAP_USER, SAP_PASSWORD. Optional: SAP_COMPANY_CODE (default 1000), CANCEL_MODE (exclude is the default; mirror keeps cancelled invoices and loads their cancellation as a credit note). Type them here only. Never send them to anyone, and never put them in a file or a chat.
  3. Run sapVerifyMetadata. It lists every SAP service, entity set and field as ok or GAP. If anything says GAP, or you see a message about 403 or an IP allow-list, send the message (not the password) to the Delivery Lead.
  4. Run sapShadowRun. It reads October 2026 from SAP, compares it with what the Desk already holds from your uploads, and writes nothing. Look at the differences per plant and month. If they are all equal, October can be replaced by the feed.
  5. Run sapSync. It reads SAP (only 1 Oct 2026 and later; data to 30 Sep 2026 is never touched) and parks the rows. If it says it stopped at the time limit, run it again; it carries on where it stopped.
  6. Open the Desk › Data Intake › SAP S/4HANA live feed. The card shows connected or not, the last run, rows read, rows loaded, errors and the next step. Click Load SAP feed. The Desk checks the rows exactly as it checks an uploaded S/4 register and replaces whole plant-months. If a month would get fewer lines than it holds, the card stops and asks you to tick a confirmation.
  7. Credit memos whose S/4 product codes are not in the item master are not loaded, and credit coverage is not marked for that month. The card says how many lines and codes. Load the item master with the S/4 codes, then click Load SAP feed again.
  8. When all of this is clean, run sapInstallDailyTrigger for one daily run (about 02:30 IST). sapRemoveDailyTrigger switches it off. The daily run only fetches; a Super admin still clicks Load SAP feed.
Later versions: paste the new Index file, then Deploy › Manage deployments › pencil › Version: New version › Deploy. The link stays the same.
